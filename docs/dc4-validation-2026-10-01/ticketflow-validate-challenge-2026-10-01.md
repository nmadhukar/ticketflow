## 2. Issues every earlier phase missed

1. **Unauthenticated-cost AI endpoints (I3 authorization gap).** `POST /api/ai/analyze-ticket` and `POST /api/ai/generate-response` require only `isAuthenticated` (`routes.ts:3553,3581`). The requirement says *agents* can analyse; in fact any customer account can drive Bedrock invocations directly, with no role gate and no rate limit (Y6 disabled). The same pattern holds for `POST /api/chat`. This is a cost-abuse hole in the product's core AI promise that none of the three earlier reports mention.
2. **Latent defect framing for I2.** All phases treat the `'system'`-user FK failure as an active break. It is unreachable without a configured Bedrock returning ≥0.7 confidence — worth stating plainly so the fix list orders it correctly (real, but fires only once AI is switched on, at which point the flagship auto-response feature silently never works).
3. **`getTasks` N+1 query loop.** For every ticket in a list, `getTasks` runs a separate `SELECT` per creator and per assignee (`storage.ts:595-650`). The list endpoint — the most-hit route in a helpdesk — scales linearly in queries per row. Noted nowhere; it becomes a production problem long before the lexicographic ticket-number overflow (F22) that the cold review did flag.
4. **PATCH NaN-id inconsistency.** `GET /api/tasks/:id` validates `isNaN` → 400 (`routes.ts:197-199`), but PATCH (`routes.ts:307`), DELETE (`379`), comments (`399,421`) and attachments do not — a non-numeric id becomes `NaN` and surfaces as a 500. The cold review covers this under P1/F24 but neither the map nor the runtime report isolates it; a client typo on any mutating route yields a server error, not a client error.
5. **`verify.sh` mount defect is worse than "tests didn't run".** The gate log (line 855) shows the exact `read-only file system` mount failure for `${PREFIX}_deps → $REPO_DIR/node_modules`. Because `run_node` mounts a volume inside the `:ro` source bind (`scripts/ai/verify.sh:50-55`), **every Node step — npm ci, lint, typecheck, Jest — fails before executing**, meaning the gate's 8 passes are infrastructure-only and its 7 failures include 5 that never tested anything. The gate cannot pass even with a perfect product until this is fixed, which the cold review says, but the map/runtime reports both treat their own local runs as evidence the suites "fail on product defects" — in the independent gate, no suite ever ran.

## 3. My verdict

The cold review is accurate and, if anything, slightly conservative. On the ten highest-stakes verdicts I agree with all ten, each confirmed at file:line level: the primary create is broken (T1), delete always 500s (T16), staff isolation is dead code (Y4), password hashes leak to any authenticated user (Y5/F2), invitation-by-email grants roles without a token (F3), a known-password admin is seeded everywhere (F1), the flagship AI auto-response can never post its comment (I2), real-time notifications are a stub (E5), revoked invitations still work (G7), and login brute force is unthrottled (Y6/A8). The product cannot be used for its core promise today: a customer cannot create a ticket through the documented API or the UI form, and if one is created by workaround, it cannot be deleted and is visible to every staff account. Where I differ from the cold review: (a) I would label I2 *latent* rather than broken — it fires only once Bedrock is configured, which matters for fix ordering; (b) I add one authorization gap the cold review missed (AI endpoints open to customers, a cost-abuse hole); (c) on T13 I side with the cold review against the runtime phase but for a stronger reason than stated — close/reopen, history writes and the activity feed all work, so the runtime FAIL belongs entirely to T17's missing read route; (d) I put more weight on the gate-harness defect: the independent gate never executed a single test suite, so its FAIL understates how little is actually verified, and the repo remains ungatable even after the product is fixed until verify.sh stops mounting into a read-only tree. Net: NOT DONE — 4 Critical security defects, a broken create/delete core loop, absent staff isolation, and a gate that cannot currently exercise the product.
